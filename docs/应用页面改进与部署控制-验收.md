# 应用页面改进与部署控制

本次围绕第一次使用平台的用户，完成“准备资源 → 创建应用 → 部署 → 查看实际网站”的引导。完整控制台入口仍是 [云端控制台](http://127.0.0.1:18780/#/applications)，需要现有 SSH 隧道和云端账号登录。

## 页面变化

- 导航改为“我的资源”“我的应用”，资源页增加部署入口，明确资源租约和应用运行状态的区别。
- 创建应用选择可用资源，避免复制租约编号。当前模板明确为欢迎页面，包含真实 React 前端和 Spring Boot 后端，不宣称可以部署任意源码。
- 欢迎语与发布操作放在左侧，实际访问地址、复制按钮、新窗口入口及网站预览放在右侧。预览加载的是已发布应用的真实网址；尚未部署和已停止时展示对应空状态。
- 部署进度使用实际任务状态和 Runner 阶段事件，执行日志、历史版本恢复和应用密钥放入折叠详情。
- 应用地址只接受无内嵌凭据的 HTTP(S) URL；预览限定跨源，使用 iframe sandbox。HTTPS 页面不会嵌入 HTTP 内容，会引导新窗口查看。
- 轮询串行执行，任务执行中约2秒、空闲约12秒；隐藏页面暂停请求。提交幂等键在计划生命周期内保持不变，报错后可以使用同一键重试。
- 单独修改欢迎语保留已有密钥；高级密钥配置明确说明完整替换语义，要求勾选确认。

## 三个不同操作

| 操作 | 实际行为 | 保留内容 |
|---|---|---|
| 取消本次部署 | 排队时直接取消；执行中申请取消，Runner 清理本次候选容器和网络后才确认取消 | 当前已发布版本、租约和配置 |
| 停止应用 | 停止当前版本的前后端容器，网站暂时无法访问 | 同一容器、版本、配置和租约，可再次启动 |
| 释放资源 | 现有资源退租流程，清理应用并结束租约 | 保留业务历史记录，不自动退款 |

取消部署和最终发布切换共用服务端主机行锁与执行代次校验。取消先获得许可时拒绝发布；发布切换先获得许可时取消返回409 `PUBLISH_IN_PROGRESS`，页面提示完成后停止或回滚。不会把已经切换的版本显示为取消成功。

清理无法确认或执行中断时任务进入 `MANUAL_REQUIRED`，继续阻塞后续发布，等待管理员核实。不会通过停止 Runner 进程冒充安全取消。

## 接口与兼容性

- `PATCH /api/projects/{id}/welcome`：只更新欢迎语，保留加密密钥。
- `POST /api/plans/{id}/cancel`：放弃未提交的操作计划。
- `POST /api/deployments/{id}/cancel`，请求 `{"confirmed":true}`：取消部署或回滚。
- 现有计划流程新增 `START`、`STOP` 类型，仍必须预览并明确确认。
- Runner 内部新增 `control`、`commit` 检查点接口，绑定已有主机凭据、任务代次与 attempt，不注册为 AI 工具。
- V007 新增控制表与应用运行状态表，不修改已应用迁移。旧 Runner 可继续原有流程；在线取消和应用启停要求执行协议2。前端新增运行状态、当前发布信息字段，原接口保留。

## 实际验收（2026-11-06）

Java 三层架构及业务回归61项、Runner 回归10项、前端 URL/状态与请求超时回归5项、React 生产构建通过。新增 Java 测试覆盖确认、所有权、旧代次、发布互斥、候选清理回执、停止启动和欢迎语保密钥。

云端执行 `tests/application_controls_acceptance.py`，在独立命名的演示租约上使用模拟支付，不真实扣款、不购买资源。验证结果：

1. 实际部署成功，公网 React 页面与 `/api/hello` 返回配置的欢迎语。
2. 排队部署取消后没有创建容器。
3. 新候选容器启动后暂停该候选，申请取消；最终状态 `CANCELLED`，候选容器和网络为空，原容器编号、当前发布编号及网站响应保持不变。
4. 停止操作真实停止两个应用容器，容器与发布记录仍保留。
5. 启动后恢复同一组容器，欢迎语与原发布版本保持一致。
6. 控制面健康检查与 Video Two 服务在应用操作后仍正常。

另用已有独立账号实测读取项目及取消其他用户部署均返回404。本地 Java/Python 服务已恢复运行，旧 Runner 已升级并保留注册凭据与回执。最终云端 HTML 与本次前端构建一致；云端观察可用内存约657MiB，Swap使用为0，未执行整机重启。

验收结束并确认用户使用普通账号登录后，已释放专用验收租约，恢复这台2GB机器唯一应用槽的可售状态，避免测试记录阻止用户自行下单。实际运行与清理证据在忽略目录 `runtime/ecs-linux/application-controls-acceptance.json`，不提交账号、密钥或 Runner 配置。

## 更新与回退

`deploy/update_application_controls.py` 仅更新授权 ECS 的业务镜像、Runner 源码及静态前端；先确认无执行中任务，再备份数据库、原镜像、网站和 Runner 回执。使用本机已有业务镜像作为基础增加 JAR 层，无需访问镜像仓库。V007 加表兼容原版本，但回退旧版本将失去新控制功能。

本次受限演示仍共用2GB主机；停止应用不停止整台 ECS，不影响控制面及 Video Two，租约和计费继续。正式生产隔离与 HTTPS 仍按原上线清单处理。
