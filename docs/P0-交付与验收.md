本版 ECS 可购买；GPU、RDS 仅展示，未配置供应能力时无法报价/下单。仅支持预付费1、3、12个月，不提供按量计费或自动续费。

默认报价10分钟、付款15分钟，可通过 `PLATFORM_QUOTE_MINUTES`、`PLATFORM_PAYMENT_MINUTES` 调整。账号最多20台活动、待履约和待支付实例，每单1~10台；SKU可配置磁盘/带宽/镜像/周期、宽限期及退款期限。

本地种子规则：首次开通后7天内按剩余租期比例退款，失败项全额退。已履约续费、已续费资源的复杂退订需工单处理，不自动承诺可退。这是订单规则快照中的模拟规则，不是知识文档中的真实商业政策。停止不延长租期，不自动退款。

## 关键接口

非流式响应为 `code/message/data/requestId`。访问需要 `Authorization: Bearer <access_token>`；用户接口不接收可覆盖身份的 `user_id`。HTTP 401/403/404/409 分别对应认证、权限、不存在或非本人对象、状态/幂等冲突。

|---|---|
| 认证 | POST `/api/auth/register`、`login`、`refresh`、`logout` |
| 用户 | GET/PATCH `/api/me`；POST `/api/me/password`、`/api/me/avatar` |
| 商品 | GET `/api/products`、`/api/products/{id}`、`/api/products/{id}/skus`、`/api/regions`、`/api/images` |

| 实例 | GET `/api/instances`、`/api/instances/{id}`、`/api/instances/{id}/metrics`；POST `/api/instances/{id}/actions` |
| 续费 | POST `/api/instances/{id}/renewal-quotes`、`/api/renewal-orders` |

列表分页为 `page`、`size`，默认20；商品默认12。商品额外接受 `keyword/category/region/cpu/memory_gb/min_price/max_price/sort`；价格筛选是SKU基础月价，最终磁盘和带宽费用另算。`sort` 为 `name/price_asc/price_desc`。

报价示例：

```json
{"sku_id":"ecs-1","image":"ubuntu-22","disk_type":"ESSD","disk_gb":40,"bandwidth":1,"months":1,"quantity":1,"name":"我的云服务器"}
```

下单只发送 `{"quote_id":"报价编号"}`，并携带8~100位 `Idempotency-Key`。同用户同键同报价返回同一订单，不同报价返回409。资源操作也携带幂等键，`action` 为 `START/STOP/RESTART/RELEASE`，释放额外需要 `confirmed:true`。

模拟付款发送 `{"confirmed":true}`；测试渠道失败/取消时可加 `"outcome":"FAILED"` 或 `"outcome":"CANCELLED"`，默认成功。此接口只写模拟渠道结果，商户订单和实例由任务查询/回调核验后变更。失败不自动关闭订单，可在付款窗口内重试。

回调签名为 Base64URL 无填充的 HMAC-SHA256，签名内容：`payment_id|provider_id|amount_cents|currency|SIMULATED`，使用服务端渠道密钥，在 `X-Payment-Signature` 传递。本地模拟采用服务密钥；真实渠道必须替换成独立商户适配器与独立凭据。只持有签名也不能伪造模拟台账中不存在的成功交易。

刷新和退出使用 HttpOnly 刷新Cookie，并从 `XSRF-TOKEN` Cookie 读取值填入 `X-CSRF-Token` 头；跨站来源不在允许名单时拒绝。访问令牌不是长期保存在 localStorage 的凭据。

SSE 为 `data: {"content":"..."}`、`tool_status`、`error` 和 `done`，含心跳；终止连接会关闭下游流。Java保存会话归属与消息记录；Python保留按用户/会话隔离的短期记忆。删除的会话不能再次使用；Python不可用时旧Redis记录按TTL失效。

## 状态与恢复机制

- 订单创建、库存预留、配置快照及待处理事件在同一事务写入。用户行锁保证并发配额，SKU条件更新避免超卖。
- 支付回调与取消/关单锁定同一订单。关闭后的成功付款保留付款事实，进入异常通知与人工售后队列，不直接开通。
- 模拟供应商使用独立事务台账模拟外部提交。供应商已成功但本地未提交时，租约过期/重启后查询同一业务号，不重复创建。
- 每个实例独立履约，重试3次后进入 `MANUAL_REQUIRED`。退款中的子项不能再次重试开通。
- 通知通过outbox异步生成；业务事件号去重。通知模板在事件生成时渲染为快照，修改模板不回写旧通知。人工重试需管理员权限与原因。
- 续费与到期任务检查最新有效期；释放或退款检查资源归属和状态，原订单保留支付事实。

| 场景 | 验证方式 |
|---|---|
| 注册/登录/刷新/退出/改密撤销、角色权限、越权对象访问 | HTTP验收及Java/Python单元测试 |
| 报价参数、幂等冲突、历史金额不随改价变化 | HTTP验收并核对持久化结果 |

| 部分失败、退款额度锁定与拒绝、资源先释放后退款 | 模拟故障 + HTTP状态和实例核对 |

| 启停重启释放、续费、到期暂停、宽限期恢复/释放 | 专用模拟记录加速服务器时间字段 |

| 实际模型工具调用、身份覆盖防护、请求号贯穿、退出撤销委托 | 真实模型与MCP集成验收，不仅检查SSE能否返回 |
| 迁移数量/金额对账、SQL备份恢复 | 原表保留，恢复至独立前缀表并核对清单 |

性能基准中的“1万商品/SKU、10万订单、50并发P95<500ms”尚未进行容量压测，不作为已经达到的指标。真实支付、真实主机、外部邮件/短信、发票、自动续费、企业组织及P1知识库发布管理均未接入。

## 代码入口

- `front/platform-web/src`：React页面、API/刷新机制、SSE解析与样式。
- `business-java/src/main/java/com/cloudagent/business/controller`：HTTP 接口、Cookie 和 SSE 响应。
- `business-java/src/main/java/com/cloudagent/business/service`：认证、商品、交易、资源、运营、工单、任务和AI编排的业务规则与事务。
- `business-java/src/main/java/com/cloudagent/business/repository`、`mapper`：SQL、行锁、分页和实体 CRUD；不得反向依赖 Controller/Service。
- `business-java/src/main/java/com/cloudagent/business/integration`、`job`、`web`、`bootstrap`：外部协议、定时入口、Web 公共逻辑和迁移初始化。
- `business-java/src/main/resources/db`：版本化MySQL迁移。
- `app/infra/internal_identity.py`、`agent/core/mcp/interceptors.py`：可信上下文校验与工具身份注入。
- `deploy/backup_business.py`、`verify_backup.py`、`build_business.py`、`run_business.py`：备份、恢复演练、构建及本地运行。

三层重构的约定见 [Java三层架构与开发规范](Java三层架构与开发规范.md) 和根目录 `AGENTS.md`。2026-11-04 重构后 Java clean 构建及 18 项测试通过，包含分层约束、Service 权限/事务责任和完整/中断 SSE 存档验证；核心交易与运营 HTTP 回归通过。真实模型验收报告沿用 P0 原验收，本次未重新调用模型。
