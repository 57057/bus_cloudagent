# P1 本地运营版：交付、验收与后续接入

日期：2026-11-04。技术栈沿用 React + Spring Boot/MyBatis-Plus + Python Agent，遵守项目根目录 `AGENTS.md` 的三层架构。

用户已选定支付宝沙箱和阿里云，并明确“凭据稍后填入，先验收本地功能”。因此本轮交付目标是本地运营闭环；不把沙箱/云厂商未联调的代码算作真实接入完成。

| 外部通知 | 事务消息入队、租约、有限重试/人工重试、独立投递台账；SMTP STARTTLS与阿里云短信适配代码 | 本次只验证本地投递；SMTP/短信未联调；外部渠道不保证绝对只投递一次 |

## 二、现在从哪里体验

- 产品中心：`http://127.0.0.1:5173/#/products`，GPU、RDS、云盘的演示规格明确标为模拟。
- 用户 P1 中心：`http://127.0.0.1:5173/#/services`，侧栏名称“费用与服务”。
- P1 运营中心：`http://127.0.0.1:5173/#/admin/p1`，也可从原管理后台顶部进入。
- AI 助手：原聊天页下方增加待确认卡；另可在“费用与服务→辅助办理”查看。
- 登录窗口：“忘记密码？”进入验证码找回。

管理员凭据仍在本地 `runtime/platform-admin.json`，不要提交或公开。原账号、业务数据和登录机制保持兼容。

### 人工验收路径

1. 管理员在 P1 运营中心创建优惠券，填写兑换码、门槛、优惠额、总量和有效期。
2. 普通用户在费用与服务领取，在产品选配页选择优惠券并请求报价，确认订单金额后下单。
3. 取消待付款订单，检查优惠券回到 AVAILABLE；重新使用并模拟付款后变为 USED。
4. 管理员创建推广活动；另一个普通用户生成链接。买家通过链接进入产品，使用该链接下单；自己使用自己的链接会被拒绝。
5. 付款后查看推广者佣金；对一个子项退款后查看负数冲正。冻结至少8天，并且尚处实际退款期、存在失败未退款子项或退款处理中的订单不能结算。
6. 买家申请发票，运营用 SIM- 开头编号模拟审核。退款后已处理发票进入 NEEDS_RED，运营模拟红冲后买家可重新申请净额。
7. 管理员草拟产品知识并提交。另一位 OPERATOR/ADMIN 审核发布；自己审核会返回409。修改已发布内容必须创建修订版。
8. 下架或到期后，新检索不得再包含这份内容。托管运行模式不回退到原 mock_data/旧图谱作为发布依据；没有有效资料时明确返回资料不足。
9. 买家对某实例授权模拟自动续费，设置单次上限。低于报价时失败并通知；提高授权、重新开启后可重试。取消只阻止后续周期，不承诺撤销已经提交的本期付款。
10. 用户请求绑定邮箱/手机。LOCAL模式下管理员在“外部通知→本地收件箱”查看10分钟内模拟验证码，用户完成验证后可在登录页找回密码。
11. AI 准备预览后，用户核对页面卡片再点击确认。确认购买/续费只创建待付款订单，不能自动扣款；确认退款只提交待审核申请。

开启全套 Python/Agent 服务之前，普通业务仍可独立使用。当前本地验收不要求模型、Milvus、Redis或Neo4j在线；自然语言聊天需另按原完整启动流程启动这些服务。

## 三、三层与一致性

```text
React
  → Marketing/Invoice/Knowledge/Contact/Renewal/AssistantAction/Provider Controller
  → 同领域 Service（输入验证、归属、权限、计算、事务）
  → 同领域 Repository（SQL、行锁、条件更新）
  → MySQL

P1JobRunner → DeliveryService / RenewalService / ProviderService
Python Agent → 签名上下文 + 受控 MCP 工具 → Java Service
```

- 新输入使用 `dto/P1Requests` 的 record 和 Bean Validation；关键复杂响应在 `P1Responses` 中定义。
- 优惠券计价进入报价快照，下单再锁券。关闭订单释放预占，合格支付才核销。至少保留1分钱订单应付，不建立零元支付旁路。
- 折扣后的子项金额以整数分分摊，余数分配到最后一项。佣金计算使用万分比，不用浮点数。
- 活动规则修改递增版本，专属链接和订单固化版本/比例；停用后不接受新归因，历史订单仍按原快照记账。
- 退款成功与佣金冲正、发票失效提示处于同一商户事务中。冲正按累计净实付的目标佣金与已有净佣金差额计算，避免多次部分退款产生舍入差。
- 自动续费先持久化并提交续费订单/支付号，之后再模拟付款；重启恢复复用已保存支付号，遵循原付款和履约状态机。
- 找回验证码保存带服务端密钥的 HMAC，最多猜测5次、10分钟过期且单次消费。按服务端观察到的来源和目标地址限频；失败计数先提交再返回错误。
- 定时线程池隔离通知与渠道网络延迟，原任务租约、资源操作版本和 outbox 保留。
- 知识发布/过期有效集参与缓存指纹。检索前后重新检查有效发布ID；旧缓存和旧向量不能成为下架文档的回流路径。

## 四、主要 API

普通接口仍为 `code/message/data/requestId` 包装；内部工具保留 `status/data`。所有用户编号从认证身份取得。

| 范围 | API |
|---|---|
| 优惠券 | GET `/api/coupons`；POST `/api/coupons/claim`；后台 GET/POST `/api/admin/coupons`、PATCH `/{id}` |
| 推广 | GET `/api/promotion/campaigns`；POST `/api/promotion/campaigns/{id}/links`；GET `/api/promotion/commissions` |
| 推广运营 | GET/POST `/api/admin/campaigns`；GET `/api/admin/commissions`；POST `/api/admin/commissions/{order}/settle` |
| 发票 | GET/POST `/api/invoices`；后台 GET `/api/admin/invoices`、POST `/{id}/review`、`/{id}/void` |
| 报表 | GET `/api/admin/reports?from=YYYY-MM-DD&to=YYYY-MM-DD`，最多366天 |
| 知识 | GET/POST `/api/admin/knowledge`；GET `/{id}`；POST `/{id}/transition`，动作 SUBMIT/PUBLISH/REJECT/RETIRE |
| 发布快照 | GET `/internal/knowledge/snapshot`，服务令牌认证，仅返回有效公开资料 |
| 联系方式 | GET `/api/me/contact`；POST `/api/me/contact/request`、`verify` |
| 找回 | POST `/api/auth/password-reset/request`、`confirm`，不在响应中返回验证码 |
| 通知 | GET `/api/admin/deliveries`、`/inbox`；POST `/{id}/retry` |
| 自动续费 | GET `/api/auto-renewals`；PUT `/api/instances/{id}/auto-renewal` |
| 辅助办理 | GET `/api/assistant/actions`；POST `/preview`、`/{id}/confirm` |
| 渠道 | GET/PUT `/api/admin/providers`；POST `/api/admin/providers/aliyun/dry-run` |
| 支付宝沙箱 | POST `/api/orders/{id}/sandbox-payment`；GET `/api/payments/{id}/sandbox-qr`；POST `/api/payments/callback/alipay-sandbox` |

## 五、启动、配置与数据

```powershell
# 在 cloud_agent 根目录
.\.venv\Scripts\python.exe deploy\build_business.py
cd front\platform-web
npm.cmd run build
cd ..\..
.\.venv\Scripts\python.exe run_local.py --business-only
```

`build_business.py` 执行 clean、编译、架构检查和 Java 测试。已有服务需要按原 README 的已登记进程重启流程重启，单纯重复启动不会替换正在运行的 JAR。

数据库仅追加 `V003__p1.sql`，原 V001/V002 校验和不变。新增业务表使用 `p1_*`；原 `p0_*` 和历史表保留。演示 SKU 由 `platform.demo` 显式初始化，不在正式部署自动开售。

P1迁移前备份：`runtime/backups/20261104-155914`。备份含凭据/验证码等可能存在的业务内容，应留在本地受控目录，不上传公开仓库。

回滚不能只换回旧 JAR 继续处理 P1订单：旧版本不知道优惠券占用、佣金冲正等规则。应先停止写入，验证备份到独立库/独立表，再协调恢复前后端及完整数据；不直接 DROP P1表或覆盖已有订单。

### 稍后接入支付宝沙箱和阿里云

1. 复制 `business-java/config.example.env` 为同目录 `.env`，填写实际沙箱账号与密钥文件路径。Windows路径建议写为 `D:/.../key.pem`。
2. 支付宝私钥为应用私钥，公钥为支付宝公钥，两者不可混淆。应用ID、商户ID必须匹配同一沙箱账号。SDK固定沙箱网关，密钥不进入数据库或接口响应。
3. 管理员在渠道页将 ALIPAY_SANDBOX 设为 SANDBOX。创建新的待付款订单后选择沙箱付款，使用沙箱买家完成支付，再核对查询、回调、重试和退款。
4. 阿里云填写最小权限 RAM AccessKey，在渠道页保存 RegionId、ZoneId、InstanceType、ImageId、SecurityGroupId、VSwitchId，并设为 DRY_RUN。点击预检只执行 DryRun，不创建收费实例。
5. 外部邮件选择 `P1_DELIVERY_MODE=SMTP` 并配置 STARTTLS邮箱；短信选择 ALIYUN_SMS 并配置已审核模板。验证码模板使用 `code` 参数，业务通知模板使用 `content` 参数。后台 DELIVERY=DISABLED 可以停止投递，环境变量变更需要重启。

本轮按用户要求没有填造账号、没有发送真实通知、没有做真实扣款或创建收费云资源。

协议参考：[支付宝官方 Java SDK](https://github.com/alipay/alipay-sdk-java-all)、[阿里云 RunInstances/DryRun](https://www.alibabacloud.com/help/en/ecs/developer-reference/api-ecs-2014-05-26-runinstances)、[Spring JavaMailSender](https://docs.spring.io/spring-framework/docs/6.0.x/javadoc-api/org/springframework/mail/javamail/JavaMailSenderImpl.html)。
