## 操作流程

管理员：原SKU后台创建adapter=POOL规格 → 登记平台资产与采购期限 → 生成单次令牌 → 在目标Linux主机安装Runner并指定批准镜像 → Docker和摘要检测通过后IDLE → 才能出售。数量由真实在线空闲池决定，不能靠手填库存伪造容量。

用户：选购平台池套餐并付款 → 获得独占分配 → 工作台绑定租约创建项目 → 可保存配置新版本 → 准备部署并核对计划 → 点击确认 → 查看任务、事件与访问URL。

故障时先确认采集运行证据，再查询诊断。重启和回滚需要新的确认计划。API_TOKEN配置是完整替换，留空表示移除，不会读回原值。应用回滚不恢复数据库或用户文件，当前模板没有用户持久卷。

## 构建与启动

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe deploy\build_business.py
npm.cmd --prefix front/platform-web run build
.\.venv\Scripts\python.exe run_local.py --skip-knowledge-sync
```

仅业务：run_local.py --business-only。已有Runner登记时启动器尝试恢复VM和Runner；失败不阻断普通交易。更新Runner源码：

```powershell
.\.venv\Scripts\python.exe deploy\start_application_runner.py --update
```

本地Runner登记路径在runtime/application-runners.json，文件只存管理路径。Linux侧的私有config.json和SQLite回执必须保留，不能为重试清空回执。

deploy/build_sample_application.py构建批准的样例镜像，不执行Docker prune。Runner更新时登记摘要并保留历史镜像对用于回滚。普通用户不能上传任意镜像、Dockerfile或脚本进入批准集合。

tests/application_acceptance.py setup仅用于首次开发fixture，同一VM已登记Runner时拒绝再登记为另一台资产。正常纳管使用管理员接口，不依赖测试账号。

## 安全和恢复边界

- 本地明确启用allow_local_http，仅面向本机/VM；公网需要TLS及受控入口，不直接暴露开发配置。
- 主机凭据与用户JWT、MCP服务令牌独立。撤销或泄露处置需要管理员确认实际主机状态。
- 超时不等于未执行；MANUAL_REQUIRED不能自动换任务号重跑。管理员先对账，再准备新计划。
- 已失败清理可显式重试本allocation的幂等清理，未知/中断发布不自动重放。
- 密钥只在DEPLOY/ROLLBACK下发，使用0600临时env文件，执行结束删除；日志有已知密钥替换、敏感模式脱敏与长度限制。
- 加密主密钥默认runtime/application-secret.key，可用APPLICATION_KEY_FILE指定；与数据库分开受控备份。SQL备份只记录指纹，不复制密钥；丢失原密钥无法恢复既有密文。
- backup_business.py排除restore_<12位hex>_演练副本，恢复脚本使用独立前缀，不覆盖原业务表。
